# Crelate — Integration Meta Skill

HOW in `lib/crelate.py`. Docs: help.crelate.com/en/articles/4120534-api-key-management-and-documentation.

## Auth & config (API key)
- **Connect (BYOK):** dashboard **Integrations → Crelate** — paste the **API key**, then **Save and test**. CLI: `hyreflow byok set crelate --api-key <key>`.
- **Get the key in Crelate:** open **Your Profile & Preferences** (Settings → My Settings & Preferences) → **API Access** and turn on **Enable API Access**; the key is generated the first time you enable it. A user without the permission needs an admin to allow it: **Security → User Roles →** the role **→ Misc → API Access = Allowed**. API access needs Crelate's Business plan or higher.
- The key acts as the user who created it, so what it can read or write is that user's access. Each member connects their own key (the owner's key is the workspace key); until a member adds theirs, Crelate won't run for them. Regenerating or disabling it in Crelate breaks the connection until the new key is pasted.
- Hyreflow paces all Crelate calls at 100 requests/minute (Crelate limits by caller IP, about 120/min). Each `list_*` call returns one page: `offset` from 0, `limit` at most 200 (a larger value is rejected, not trimmed); the `search_*` calls take `limit` at most 100. Keep raising `offset` while the response's `Metadata.MoreRecords` is true.

## Operations
Read: `ping`, `list_contacts` / `search_contacts` / `get_contact`, `list_jobs` / `search_jobs` / `get_job`, `list_workflow_statuses`, `list_companies` / `search_companies` / `get_company`, `list_notes`. Write: `create_contact`, `update_contact`, `add_contact_to_job`, `create_note`. Bulk: `create_contacts_batch`, plus the generic `batch` for get/search/update/create calls (see `crm-bulk-pushes.md`).

## Notes & guardrail
- **Vocabulary:** a Crelate *contact* is any person — a candidate and/or a client contact, told apart by `RecordType`. A *company* is an account, a *job* is a role, and a *workflow status* is a pipeline stage.
- **Filtering:** `list_contacts` takes filters such as `emails`, `phone_numbers`, `job_ids`, `record_types`, `statuses`, `tag_names`, `modified_after` and `sort_by`; `list_jobs` and `list_companies` have their own. `search_*` is a keyword search that returns summary fields only: use `get_*` for the full record.
- **`create_contact`** takes the record's own fields: `{"FirstName": "Jane", "LastName": "Doe", "EmailAddresses_Work": {"Value": "jane@acme.example", "IsPrimary": true}, "Websites_LinkedIn": {"Value": "https://www.linkedin.com/in/jane-doe"}, "PhoneNumbers_Mobile": {"Value": "+14155550123"}}`. Phone numbers are E.164 with the leading `+`. The call returns the new contact's id.
- **Duplicates:** Crelate answers a create that matches the workspace's duplicate rules with a 409. Check `list_contacts` with `emails` first, and update the match with `update_contact` instead of creating a second record.
- **Required fields** are configured per Crelate account, so a create can be refused for a field your account makes mandatory: create one record and read the error before a bulk push.
- **`update_contact`** is a partial update: only the fields you send change. `Tags` is replaced whole, so send the full list.
- **`add_contact_to_job`** puts a contact on a job's pipeline at a stage, named by exactly one of `status_name` or `status_id`. Read the stages with `list_workflow_statuses` first.
- **`create_note`** takes `{"Display": "Spoke on Monday", "ParentId": {"Id": "<contact id>", "EntityName": "Contacts"}}`, plus an optional `RegardingId` (`{"Id": "<job id>"}`) and `When`.
- There is no record delete.
- Production ATS writes — pilot one record, confirm, then bulk.

## Handoff
ATS write target: enriched candidates → `create_contact` (or `create_contacts_batch`), then `add_contact_to_job` to place them on a role; reply or call notes → `create_note`.
Company-first BD: `list_companies` → each company's website → `hyreflow_native` career-page scraping for their open roles → contacts via the `people_search` waterfall.

## Bulk writes & rate limits

For large pushes use `create_contacts_batch`. It paces calls to the **100 req/min** default and returns
`{created, failed, total, elapsed_ms}`. See `crm-bulk-pushes.md` for the cross-CRM guide.
