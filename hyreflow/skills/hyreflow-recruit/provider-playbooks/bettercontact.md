# BetterContact Agent Guidance

> **Channel: WORK email only (BD / selling to companies).** `enrich_email_address` returns a corporate
> address at the person's current employer (`data[].contact_email_address`) — never a personal one. It is
> not in the `email_enrichment` or `personal_email` waterfalls (it does run in the `phone_enrichment`
> chain, phone-only) and must not be used to serve a work email on a candidate / `personal_email`
> pipeline, including as a fallback when that waterfall returns fewer hits than hoped. A work-email request's
> responses carry `_meta.channel: "work_email"` and a `work_email_only` warning as the engine-side reminder,
> and a request whose body declares `"channel": "personal"` / `"personal_email"` / `"candidate"` is refused
> (`400 work_email_only`) before any credit is spent — unless the request asks for a phone only
> (`enrich_email_address: false, enrich_phone_number: true`), which is how the `phone_enrichment`
> waterfall calls it and skips both the refusal and the work-email meta/warning.

**BYOK-only.** Hyreflow holds no BetterContact account, so BetterContact runs only on a workspace's own
connected key and costs 0 hyreflow credits; the workspace pays BetterContact directly. With no key
connected, a BetterContact call answers `no_key` and its `phone_enrichment` step is skipped with no call and
no charge. Connecting a key needs the Essential plan or above.

## Key patterns

- **Enrichment is async.** `bettercontact_start_enrichment` launches a BetterContact job (one method — it always accepts a list, so single and bulk both go through it) and returns a request id immediately. Use `bettercontact_get_enrichment` to fetch terminal results.
- **Email status hierarchy:** deliverable > catch_all_safe > catch_all_not_safe > undeliverable. Only trust deliverable and catch_all_safe for outreach.
- **Batch up to 100 contacts** per `bettercontact_start_enrichment` request.
- Use the launcher response `id` as the `request_id` for `bettercontact_get_enrichment`.
- **Rate limit:** 60 requests per minute per API key, shared across all endpoints.

## Pricing

- 0 hyreflow credits (BYOK-only). The job spends BetterContact credits on the workspace's own account, only
  for a result that carries data: not-found and catch-all rows are free on BetterContact's side.
- `bettercontact_get_enrichment` returns `credits_consumed`: what the job cost on that BetterContact account.
- `enrich_phone_number: true` costs roughly ten times an email on BetterContact's side, so leave it off unless
  the play needs a phone.

## When to use

- Use BetterContact on a **work-email** (`email_enrichment` / BD) run when you need waterfall email
  enrichment with multi-provider verification.
- Good fallback on that same work-email run when single-provider work-email finders (Prospeo, Lusha) miss.
- Includes triple email verification, phone verification, contact & company enrichment.

## When NOT to use

- **Never for candidate sourcing / recruiting outreach.** The candidate channel is personal email +
  LinkedIn (`personal_email` waterfall) — a work address there is a channel-rule violation, and the credits
  are wasted because the rows must be discarded. A `personal_email` shortfall (`spending_cap_reached`,
  `still_enriching`, provider misses) is *retry later*, not a reason to call BetterContact — a
  `still_enriching` row settles on its own server-side, so there's nothing to fill in for even then.
- Don't use for email validation only — use a dedicated validator.
- Don't use for company/org enrichment — BetterContact is contact-focused.

## Callable surface
Call via the CLI: `hyreflow tools execute bettercontact <method> --payload '{...}'` (preview with `--dry-run`; `hyreflow tools get bettercontact <method>` returns the live contract + cost). Base: `https://app.bettercontact.rocks/api/v2`. Only the methods listed below are callable.

- `get_account() -> dict` — GET /account — account info + remaining credits: {success, credits_left, email} on the caller's own BetterContact account; requires the workspace's own key.
- `get_enrichment(request_id: str) -> dict` — GET /async/{request_id} — poll the enrichment result.
- `ping() -> dict` — BYOK key-verification probe — GET /account (free, no job started).
- `start_enrichment(data: list[dict], *, enrich_email_address: bool = True, enrich_phone_number: bool = False, webhook: str | None = None, **opts) -> dict` — POST /async — start waterfall enrichment for up to 100 leads. Returns {id}.
