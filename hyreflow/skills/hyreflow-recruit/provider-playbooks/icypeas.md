# Icypeas Workflow Guidance

The adapter exposes 6 methods: `icypeas_email_search`, `icypeas_domain_search`, `icypeas_email_verification`,
`icypeas_read_results`, `icypeas_subscription_information`, `icypeas_ping`. There is no count-first,
bulk-search, or LinkedIn-profile-scraping workflow for this provider today — routes like
`find_people`/`find_companies`/`scrape_profile`/`scrape_company` don't exist on this engine.

- **Email search is async.** `icypeas_email_search` returns a `SCHEDULED` status immediately (billed per
  result). Poll `icypeas_read_results` (free) with the returned `_id` to get the final email.
- **Domain search** (`icypeas_domain_search`, billed per request) is the closest thing to a company-level
  lookup this provider offers.
- **Verify before sending.** Run `icypeas_email_verification` on discovered emails before outbound. Treat
  `NOT_FOUND` and `DEBITED_NOT_FOUND` as non-deliverable. Check `hyreflow tools get icypeas <method>` for
  the live rate on each.
- **Free operations:** `icypeas_read_results` and `icypeas_ping` cost zero Hyreflow credits.
- **Don't call `icypeas_subscription_information`.** It reads Hyreflow's own Icypeas account, so the engine
  refuses it for every workspace (icypeas has no customer BYOK today). Budget a large run against
  `hyreflow billing balance` instead.

## Callable surface
Call via the CLI: `hyreflow tools execute icypeas <method> --payload '{...}'` (preview with `--dry-run`; `hyreflow tools get icypeas <method>` returns the live contract + cost). Base: `https://app.icypeas.com/api`. Only the methods listed below are callable.

- `domain_search(payload: dict) -> dict` — POST /domain-search — find emails for a domain (async).
- `email_search(payload: dict) -> dict` — POST /email-search — launch an email-finder search (async). Returns a job id.
- `email_verification(payload: dict) -> dict` — POST /email-verification — verify an email (async).
- `ping() -> dict` — Hyreflow-managed-key verification probe (icypeas has no customer BYOK today). Icypeas' subscription endpoint requires the account email, so this launches a minimal email-search (returns a job id) to confirm the key authenticates — ICYPEAS credits are charged on a found result, so a junk lead is typically free vendor-side, but NOT guaranteed. hyreflow charges 0 for this probe (`unit: free`).
- `read_results(payload: dict) -> dict` — POST /bulk-single-searchs/read — poll results for launched searches (by id/filters).
- `subscription_information(email: str | None = None) -> dict` — POST /a/actions/subscription-information — plan + remaining credits: {plan, status, credits, quotas: {daily}, currency} — NOT callable by a workspace. It reads Hyreflow's own Icypeas account, not a per-workspace one (icypeas has no customer BYOK today); the engine refuses it on the workspace path regardless. Requires that account's email in the body — a wrong email 401s.
