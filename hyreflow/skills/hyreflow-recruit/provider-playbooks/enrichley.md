# Enrichley — Integration Meta Skill

HOW in `lib/enrichley.py`. Docs cached at `reference/docs/enrichley/raw/`.

## Auth & config
- **Base URL:** `https://api.enrichley.io/api/v1` · **Auth:** header `x-api-key` (env `ENRICHLEY_API_KEY`; never hardcode). The provider caps a key at **10 requests/second** — the engine paces calls to it for you.

## Operations
- `validate_email(email)` → `POST /validate-single-email`. Specialises in catch-all/risky verdicts.
- Anything else → generic `request()`.

## Cost & failures
- **0.25 credits per verdict**, whatever the verdict. `invalid` is a delivered answer here, not a miss — the verdict is the product.
- **A call that returns no verdict costs nothing.** A provider failure comes back as an error carrying `credits_charged: 0` and the provider's `provider_status`; the balance is untouched. Don't cache such a response as if it were a verdict — check `provider_status` before treating a row as validated.
- A successful verdict also carries the provider's own `credits_consumed`. That is the provider's own metering, not what you were charged — `_meta.credits_charged` is the charge.

## Handoff
Final **deliverability gate** before sending: run emails (from Apollo/Lusha/LeadMagic/FullEnrich) through Enrichley, drop undeliverable, keep catch-alls it clears.

**Above ~50 addresses, use `hyreflow enrich`, not a per-row `tools execute` loop.** The batch path paces the provider, and every verdict lands in an output dataset you can download or re-read — a per-row loop keeps the verdicts only in the conversation, so anything you don't write down is bought again next time.
