# Wiza — Agent Guidance

## When to use

Wiza for LinkedIn → email/phone enrichment. Key advantage over ContactOut: **accepts Sales Navigator and LinkedIn Recruiter URLs** in addition to standard LinkedIn profile URLs. Strong for outbound teams with Sales Nav lists.

## Provider characteristics

- **Input required**: LinkedIn URL (including Sales Nav), email, or name+company
- **Geographic coverage**: Global
- **Credit cost**: scales with enrichment level — 1.0 credits base, rising to 2.5 for a `phone` reveal
  and 3.5 for `full`; charged once when the retrieved result carries data — check
  `hyreflow tools get wiza start_individual_reveal` for the live rate
- **Enrichment levels**: `none` (profile only), `partial` (email), `phone`, `full` (email+phone) — the level
  controls both what's returned and the price
- **Async**: reveals are queued and processed — the handler polls until finished

## Key operations

### wiza_start_individual_reveal

Starts an async enrichment job and polls until finished. Accepts any LinkedIn URL type.

```json
{
  "profile_url": "https://www.linkedin.com/in/johndoe",
  "enrichment_level": "partial"
}
```

For phones + emails:

```json
{
  "profile_url": "https://www.linkedin.com/in/johndoe",
  "enrichment_level": "full"
}
```

Name + company fallback:

```json
{
  "full_name": "John Doe",
  "domain": "acme.com",
  "enrichment_level": "partial"
}
```

### wiza_prospect_search

Discover prospects by job title, level, company, industry, location. **Free** — returns masked profiles without contact info. Returns up to 30 results per search.

```json
{
  "filters": {
    "job_title": "VP of Sales",
    "job_level": "vp",
    "company_industry": "SaaS",
    "person_location": "United States"
  }
}
```

Typical flow: search → get LinkedIn URLs → feed into `wiza_start_individual_reveal` to enrich.

## Output shape

`wiza_start_individual_reveal` returns a flat object. Email at `email`, phones at `phone_number1`, `mobile_phone1`. Status at `status` ("finished" | "failed").

`wiza_prospect_search` returns `{ prospects: [...], total: N }`.

## Enrichment levels

| Level     | Returns             | Cost      |
| --------- | ------------------- | --------- |
| `none`    | Profile data only   | 1.0 cr    |
| `partial` | Emails only         | 1.0 cr    |
| `phone`   | Phone numbers only  | 2.5 cr    |
| `full`    | Emails + phones     | 3.5 cr    |

Pricing is billed once, on retrieval, when the result carries data — the `enrichment_level` you request
does change the credit cost. Check `hyreflow tools get wiza start_individual_reveal` for the live rate.

## Anti-patterns

- Don't over-request `enrichment_level: "full"` reflexively — it costs more than `partial` (3.5 vs 1.0 credits) and a phone match takes longer/is less reliable, so only ask for it when the workflow actually needs a phone number
- Don't skip polling — reveals are async, status starts as "queued"
- Don't expect more than 30 results from search per call

## Callable surface
Call via the CLI: `hyreflow tools execute wiza <method> --payload '{...}'` (preview with `--dry-run`; `hyreflow tools get wiza <method>` returns the live contract + cost). Base: `https://wiza.co/api`. Any endpoint without a typed method is reachable through the tool's generic `request` passthrough.

- `continue_prospect_search(list_id: str | int, *, max_profiles: int | None = None, callback_url: str | None = None) -> dict` — POST /prospects/continue_search — fetch more results into an existing prospect list (pagination). `id` = the list to continue. Returns the list object (data.id, stats).
- `create_list(name: str, items: list[dict], *, enrichment_level: str = 'partial', email_options: dict | None = None, callback_url: str | None = None, **opts) -> dict` — POST /lists — bulk-enrich provided `items` (each: {profile_url} OR {full_name,company/domain} OR {email}), up to the plan limit. `enrichment_level` none/partial/phone/full. Returns data.id; poll get_list(id) until `finished_at` set, then get_list_contacts(id).
- `create_prospect_list(name: str, filters: dict, *, max_profiles: int = 10, enrichment_level: str = 'partial', email_options: dict | None = None, callback_url: str | None = None, **opts) -> dict` — POST /prospects/create_prospect_list — turn a prospect search into a revealed list (ASYNC, CHARGED: consumes WIZA credits vendor-side and hyreflow credits per this method's `cost` block — unlike the free masked `prospect_search`). `filters` same shape as prospect_search.
- `enrich_company(*, domain: str | None = None, name: str | None = None) -> dict` — POST /company_enrichments — SYNC company enrichment by `domain` OR `name`. Returns firmographics (industry, size, founded, revenue_range, linkedin, …) immediately.
- `get_credits() -> dict` — GET /meta/credits — account balances (email_credits/phone_credits/api_credits/export_credits) on the caller's own Wiza account; requires the workspace's own key. Values may be "unlimited" or a number.
- `get_individual_reveal(reveal_id: str | int) -> dict` — GET /individual_reveals/{id} — poll a reveal. Terminal when data.status is 'finished' or 'failed' (data.is_complete). Email at data.email / data.emails[]; phone at data.phone_number / data.phones[].
- `get_list(list_id: str | int) -> dict` — GET /lists/{id} — list status. Terminal when data.finished_at is non-null (data.status 'finished'). Carries stats.credits.
- `get_list_contacts(list_id: str | int, *, segment: str = 'people', **params) -> dict` — GET /lists/{id}/contacts?segment= — enriched results. `segment` (REQUIRED) ∈ people|valid|risky. Each contact: email/email_type/email_status, name, title, company, linkedin.
- `prospect_search(filters: dict, *, size: int = 10) -> dict` — POST /prospects/search — masked preview (FREE, no contact info, max 30). `filters` use the Wiza shape: text filters as [{"v":val,"s":"i|e"}], locations add "b":"city|state|country"; enum filters (job_title_level, company_size, …) as arrays. Returns data.total + data.profiles[].
- `start_individual_reveal(*, profile_url: str | None = None, full_name: str | None = None, company: str | None = None, domain: str | None = None, email: str | None = None, enrichment_level: str = 'partial', email_options: dict | None = None, callback_url: str | None = None, **opts) -> dict` — POST /individual_reveals — start an async reveal. Identify by ONE of: `profile_url` (LinkedIn incl. Sales Nav/Recruiter), `full_name`+(`company` OR `domain`), or `email`.
