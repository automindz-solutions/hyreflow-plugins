# TrackerRMS — Integration Meta Skill

HOW in `lib/trackerrms.py`.

## Auth & config
TrackerRMS connects over OAuth, self-serve from the dashboard's TrackerRMS card: the workspace pastes
the client secret Tracker support issued (with the hyreflow redirect URI registered), picks its region
— Tracker's OAuth hosts are regional — and clicks Connect. The access token refreshes automatically on
expiry and is exchanged for the API JWT under the hood.

## Operations
TrackerRMS's own nouns are not the usual ATS nouns — getting this vocabulary right is the #1 thing to get
right when talking to a TrackerRMS user:
- **Resource = candidate.** Search/get/create/update: `search_resources`, `get_resource`,
  `create_resource`, `update_resource`, plus `create_resource_from_resume` and `get_resource_skills`.
- **Opportunity = job.** `search_opportunities`, `get_opportunity`, `create_opportunity`,
  `update_opportunity`, `publish_opportunity`, plus `get_opportunity_applicants` and
  `get_opportunity_longlist` / `add_to_longlist`.
- **Client = company.** `search_clients`, `get_client`, `create_client`, `update_client`.
- **Contact = a person at a client.** `search_contacts`, `get_contact`, `create_contact`,
  `update_contact`.
- **OpportunityResource = shortlist entry / placement.** `shortlist_resource`,
  `search_opportunity_resources`, `get_opportunity_resource`, `update_opportunity_resource`,
  `get_shortlist`.
- `get_metadata` is a free read — call it before any write that needs a status/type/source/team id;
  it returns the calling user's own ids for all of them.

## Guardrail
Searches are `POST` with a search DTO, not query params. `maxResults`/`pageNumber` must be positive
integers — an out-of-range value is rejected, never clamped, so a caller's paging loop never silently
skips records it never asked to skip. Record ids are integers. No delete/destroy op is exposed. TrackerRMS
documents no idempotency key, so never blind-retry a create.

## Handoff
ATS write target: enriched candidates → `create_resource`.

## Bulk writes & rate limits

TrackerRMS publishes a hard **600** requests/minute limit — this is the vendor's published figure, not a
conservative default. For large pushes use `create_resources_batch`, `create_opportunities_batch`,
`create_clients_batch` and `create_contacts_batch`, plus the generic `batch` for any other read/update
method. They return `{created, failed, total, elapsed_ms}`. See `crm-bulk-pushes.md` for the cross-CRM
guide.

Writes cost 0 Hyreflow credits — they run on the client's own TrackerRMS account.
